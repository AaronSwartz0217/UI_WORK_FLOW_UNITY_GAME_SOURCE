# UI 正式流程补充规范

本文件记录本项目在实际制作中确认的新增硬门槛。若与早期执行习惯冲突，以本补充规范的更严格要求为准。

## 1. 原生比例生成

- 生成前必须测量白模主面板及子面板宽高比。
- 完整效果图必须从生成阶段原生接近白模比例。
- 禁止把宽版或窄版生成图通过单轴缩放强行修成目标比例。
- `ScaleX` 必须等于 `ScaleY`；不相等即为 Fail。
- 比例不合格时，只允许：原生重生成、等比缩放后裁切、等比缩放后补边。

## 2. 比例与视觉双回环

数值比例通过不代表视觉通过。每轮必须同时检查：

- 主面板和子面板宽高比；
- 横向与纵向边框厚度；
- 正方形按钮是否仍为正方形；
- 圆形、图标和符号是否发生方向性变形；
- 文字笔画是否压扁或拉长；
- 材质纹理是否因缩放变糊；
- 相对位置、层级、留白和嵌套关系。

任一项失败，资源只能留在 `into` 或移入 `into/Rejected`，不得进入正式目录。

## 3. 父板与子板

- `MainPanelBase` 只能包含大板外框与连续底材。
- 所有可见的小板必须拆成独立透明 PNG，再按原坐标覆盖到父板。
- 禁止父板烘焙子板后又重复叠加子板。
- 必须生成父子板原位重组预览，检查重边、漏缝和错位。

## 4. 按钮精度

- 关键按钮不得从低分辨率完整截图直接裁切后作为正式母件。
- 关闭按钮、页签和主要操作按钮优先独立高分辨率生成，再降采样到正式尺寸。
- 非符号按钮必须去除文字；文字由引擎文本节点渲染。
- 关闭、加减号等功能符号必须保留，并在四态中保持完全一致。
- 每个按钮交付 `Normal / Hover / Pressed / Disabled`，四态画布、轮廓、中心和锚点一致。

## 5. 正式导出目录

同一项目拆出的全部组件统一放入：

```text
Components/
└─ out/
   └─ ProjectId/
      └─ 所有正式组件 PNG
```

左右组件、父板、子板、按钮和进度条不得分散到不同项目文件夹。

## 6. 每个 UI 的固定流程

```text
读取全部输入
→ 确认命名与拆分清单
→ 测量白模比例
→ 原生比例生成完整效果图
→ 数值比例与目视精度回环
→ 用户审核完整效果图
→ 无字结构母版
→ 纯父板
→ 子板、轨道、Fill 和按钮拆分
→ 按钮四态回环
→ Alpha 棋盘格
→ 原位重组
→ 第二轮独立复核
→ Components/out/ProjectId
```

每次只完成一个 UI；用户审核通过后才继续下一个。
# 按钮 Alpha 强制规则

- 按钮是完整的实心 UI 板件，不是仅保留边框和符号的镂空图。
- 按钮外轮廓之外必须透明；外轮廓以内（边框、底板、纹理区域）必须保留完整像素。
- 禁止对按钮使用会穿透面板内部的全图差分 Alpha 蒙版。
- 非符号按钮只移除文字，不得同时移除文字下方的按钮底板和纹理。
- 符号按钮保留符号，并保留符号背后的完整按钮底面。
- Normal、Hover、Pressed、Disabled 四态必须使用相同画布、相同外轮廓和相同锚点。
- 每次导出必须抽查按钮中心点及内部安全区：Alpha 必须为 255；透明像素只能位于外轮廓之外的角部或阴影外侧。
- 透明棋盘图检查时，如果棋盘格从按钮面板内部透出，本轮 QA 直接判定为失败，修复后重新导出与回拼。
